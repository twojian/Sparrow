# 数据、判卷器与编码缓存

本文讲三件事：合成数据怎么生成、两个判卷器怎么训练、冻结 VAE 的编码缓存怎么产出。对应代码是 `code/t2i/data.py`、`train_judges.py`、`encode.py`，全部产物在 `repro/work/` 下。

结论先说：60000 张图 + 10000 段视频的训练集与 2000 + 500 的测试集建成，训练/测试零重叠（0/2000 命中）；两个判卷器在测试集上准确率均为 100%；图像编码缓存 254.0 MB，键与形状符合训练侧预期。整条链路顺序执行约 79 分钟。

## 1. 总览与耗时

| 步骤 | 命令 | 实测耗时 | 产出 |
| --- | --- | --- | --- |
| ① 测试集造数据 | `data.py world ... 2000 500 900000000` | 91 s | `world_test.npz` 122.9 MB |
| ② 训练集造数据 | `data.py world ... 60000 10000 0` | **1440 s** | `world_train.npz` 2705 MB |
| ③ 空录音占位 | 内联 numpy 脚本 | <1 s | `voice.npz` 空占位（0 条） |
| ④ 图判卷器 | `train_judges.py img --steps 2000` | 1011.9 s | `judge_img.pt` 2.26 MB + json |
| ⑤ 视频判卷器 | `train_judges.py vid --steps 1500` | 1608.5 s | `judge_vid.pt` 2.64 MB + json |
| ⑥ 图像编码缓存 | `encode.py --parts img` | 67.6 s 加载 + **1410.3 s 编码** | `img.npz` 254.0 MB、`labels.npz` 1.19 MB、`encode.json` |

数据链路全部为脚本原样运行，未改代码。全程只消费 CPU 与一张 4 GB 级显卡。

## 2. 执行步骤

### 2.0 建立工作目录

```powershell
New-Item -ItemType Directory -Force `
  "<repo>\repro\work\data", `
  "<repo>\repro\work\judges", `
  "<repo>\repro\work\cache", `
  "<repo>\repro\work\runs"
```

目录划分与代码默认口径一致：`data`（npz 原始数据）、`judges`（判卷权重）、`cache`（冻结零件的潜变量缓存）、`runs`（训练产物）。

### 2.1 生成测试集（独立种子段）

```powershell
& "<venv>\Scripts\python.exe" data.py world `
  "<repo>\repro\work\data\world_test.npz" 2000 500 900000000
```

- 每条样本的种子 = 起始种子 + 序号；图像种子段 `900000000…`，视频种子段 `950000000…`（脚本内部固定 `seed + 50_000_000` 偏移，900000000 + 50000000 = 950000000）。
- 进程池 `Pool(min(96, os.cpu_count()))`，`chunksize=32`，按 CPU 核数切分。
- 输出：`2000 张图 + 500 段视频，91 s，123 MB`。

结构校验：

| 字段 | 形状 / 类型 |
| --- | --- |
| `img` | `(2000, 64, 64, 3)` uint8，取值 0–255 |
| `img_animal` / `img_color` | `(2000,)` int64 |
| `vid` | `(500, 16, 64, 64, 3)` uint8 |
| `vid_animal` / `vid_color` / `vid_action` | `(500,)` int64 |

标签分布接近均匀（动物 309–352/类，颜色 226–275/类，动作 103–151/类），说明世界生成器抽样正常。

### 2.2 生成训练集（种子 0）

```powershell
& "<venv>\Scripts\python.exe" data.py world `
  "<repo>\repro\work\data\world_train.npz" 60000 10000 0
```

- 输出：`60000 张图 + 10000 段视频，1440 s，2705 MB`，即 **48.6 条样本/秒**。
- 训练图种子 `0…59999`、训练视频种子 `50000000…50009999`，与测试集种子段完全不交叉。

**零重叠核验**：对 60000 张训练图逐张取 blake2b-64 摘要建集合，再用 2000 张测试图查表，命中 **0/2000**；训练/测试形状分别为 `(60000,64,64,3)`、`(2000,64,64,3)`，训练标签分布 9903–10127/类。

### 2.3 空录音占位

本阶段不涉及语音，但 `encode.py` 启动时会读 `voice.npz`（主模型只在评测 a2t / a2i 时才读），缺文件直接 `FileNotFoundError`：

```powershell
& "<venv>\Scripts\python.exe" -c `
  "import numpy as np; np.savez(r'<repo>\repro\work\data\voice.npz', `
  `wav=np.zeros((0, 49920), np.float32), animal=np.zeros(0, np.int64), test=np.zeros(0, bool))"
```

回读确认：`wav (0,49920) float32`、`animal (0,) int64`、`test (0,) bool`。`49920 = 26 帧 × 1920 采样`（2.08 秒），与 `parts.py` 的 `CLIP` 一致，保证后续换真录音时结构不变。

### 2.4 图判卷器（2000 步）

```powershell
& "<venv>\Scripts\python.exe" train_judges.py img `
  --data "<repo>\repro\work\data" `
  --out  "<repo>\repro\work\judges" --steps 2000
```

- 只用真图训练，与主模型无关；结构为 4 个「3×3 卷积×2 + BN + ReLU + 2×2 池化」块 + 全局平均池化，两个线性头（动物 6 类、颜色 8 类）。
- 每步随机取 128 张，AdamW(lr 1e-3, wd 1e-4) + OneCycleLR，`torch.autocast("cuda", bfloat16)`。
- loss：`step 0 4.1676 → 500 0.0039 → 1000 0.0011 → 1500 0.0009`。
- 结果（`judge_img.json`）：`params_M 0.585`、`seconds 1011.9`、`peak_mem_GB 7.56`、**`animal_acc 1.0`、`color_acc 1.0`**。

### 2.5 视频判卷器（1500 步）

```powershell
& "<venv>\Scripts\python.exe" train_judges.py vid `
  --data "<repo>\repro\work\data" `
  --out  "<repo>\repro\work\judges" --steps 1500
```

- 逐帧共用同一个 CNN，再在时间维上做两层 Conv1d；三个头为动物、颜色、动作（4 类）。
- 每步取 16 段 × 16 帧 = 256 张图送网络，显存与算力压力约为图判卷器的 2 倍。
- loss：`step 0 5.5103 → 500 0.0684 → 1000 0.0044`。
- 结果（`judge_vid.json`）：`params_M 0.685`、`seconds 1608.5`、`peak_mem_GB 5.28`、**动物 / 颜色 / 动作准确率均 1.0**。

> 训练只用图判卷器，但 `encode.py` 启动时会同时加载两个权重，所以两条命令都必须跑。

### 2.6 编码缓存（只编 img）

```powershell
& "<venv>\Scripts\python.exe" encode.py `
  --data   "<repo>\repro\work\data" `
  --judges "<repo>\repro\work\judges" `
  --out    "<repo>\repro\work\cache" --parts img
```

- 脚本先写 `labels.npz`（每次必写），再把 60000 + 2000 张图分批（bs=256）送 FLUX.2 VAE 编码，`fp16` 存盘。
- 编码后额外解码 500 张测试图做「压了再还原」的质量检查，交给图判卷器打分。

`encode.json` 实测：

| 指标 | 值 | 基线口径 |
| --- | --- | --- |
| repo | `black-forest-labs/FLUX.2-klein-4B/vae` | 同 |
| params\_M | 84.0 | 同 |
| load\_seconds | 67.6 | 约半分钟（另加载入） |
| encode\_seconds | **1410.3** | 约 30 s |
| peak\_mem\_GB | 3.01 | — |
| cache\_MB | **254.0** | ≈0.25 GB |
| latent | `[32, 8, 8]` | 同 |
| recon\_l1 | 0.0334 | — |
| recon\_animal\_acc / recon\_color\_acc | **1.0 / 1.0** | 同 |

缓存校验：`img.npz` 键为 `train.img_lat (60000,32,8,8)`、`test.img_lat (2000,32,8,8)`，均为 float16；`labels.npz` 含 train/test 的 img/vid 标签与 `voice.*` 空数组。理论容量 `60000×32×8×8×2 B ≈ 246 MB`，与实测 242.19 MiB 吻合。

## 3. 与基线口径的差异

| 项目 | 基线口径 | 本项目实测 | 差异原因 |
| --- | --- | --- | --- |
| 造数据 60000 图 + 10000 段 | 单核 9 ms/图、0.15 s/动画，按核并行 | 1440 s（48.6 样本/s） | 原生 Windows 的进程池调度与文件写入开销高于容器；单样本 CPU 成本约为基线口径的 2–3 倍 |
| 判卷器训练 | 未给时长 | 1011.9 s / 1608.5 s | 无 Tensor Core 的硬件上 bf16 autocast 为软件模拟，吞吐低于 Ampere 及之后代际 |
| 判卷准确率 | 动物/颜色 100% | 100% / 100% / 动作 100% | 一致 |
| 编码缓存 | ≈0.25 GB、约半分钟 | 254 MB、1410.3 s | 容量一致；编码慢约 47 倍，主因同上（bf16 模拟 + 小显存），另含 67.6 s 权重加载 |
| 峰值显存 | 训练峰值约 5 GB | 图判卷 7.56 GB、视频判卷 5.28 GB | 显存回退：分配量可以超过物理容量，超出部分走内存，吞吐下降但不报错 |

这条链路的核心工程结论：显存不够时不会 OOM 失败，而是**用带宽换容量**，代价是吞吐成倍下降。因此后续训练必须主动压批大小，而不是等它变慢。

## 4. 已知风险

1. **显存超额分配**：判卷器阶段已观测到 7.56 GB 分配。训练必须压 `--bs`（基线配置 512），否则会因回退导致速度骤降；峰值需单独记录。
2. **编码缓存是「冻结零件」产物**：一旦 `frozen.py` 的 VAE 版本或 diffusers 版本变化，缓存必须重建（1410 s 的代价）。
3. **数据不可裁剪**：图判卷器与后续主模型都依赖 60000/2000 的完整切分，删数据会导致判卷器与训练全部重跑。
4. **缓存加载依赖本地权重**：`encode.json` 的 `load_seconds` 包含 Hub 在线校验；断网且本地缓存被清时会直接失败。
5. **视频数组占用大**：视频判卷器当前不用，但 `vid` 数组占 `world_train.npz` 的 1.97 GB，训练阶段加载数据时注意内存。

| 验收点 | 判定 |

| 测试集/训练集 64×64、不同种子、零重叠 | 通过（0/2000 命中） |
| 训练集 60000 图 + 10000 段并记录耗时 | 通过（1440 s） |
| 空 `voice.npz` 让 `encode.py` 不报错 | 通过 |
| `judge_img.pt` / `judge_vid.pt` 且 json 有测试准确率 | 通过（均 100%） |
| `labels.npz` / `img.npz` / `encode.json`，缓存 ≈0.25 GB | 通过（254.0 MB） |

## 6. 训练入口与验收标准

```powershell
python sparrow.py --data repro/work/data --cache repro/work/cache --judges repro/work/judges `
  --out repro/work/runs/ep02 --tasks t2i --steps 4000 --eval_every 250
python sparrow.py ... --eval_only
```

3. 记录训练峰值显存与单步耗时，与基线 `train_peak_mem_GB 4.51` 对照；若显存回退严重，记录降 `--bs` 的方案与影响。
4. `infer.py` 产出可辨认的「红色 小猫」图，并与 `repro/work/gen_test/red_cat.png` 对比。
