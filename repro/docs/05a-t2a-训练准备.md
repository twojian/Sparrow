# t2a：训练准备

本文回答的问题是`t2a`怎么从零跑到可评测：环境怎么配置、录音数据是什么样、缓存怎么编、目录怎么划分、一步训练里算什么、判分怎么判、以及验证按什么顺序走。文中的数字都标了来源：**实测**取自 `report.json` 与训练日志；**推算**是按实测外推、没有直接证据。

结论先说：t2a 与 t2i 的差别只有两处——目标从 64 个图像向量换成 104 个音频向量，判分从图像分类器换成语音识别；主干、损失、优化器、采样流程完全共用。这条链路已经在合成数据上跑通两段训练（8000 步与续训 2000 步），完整数字、逐词分布与异常检查都在 [05b-t2a-训练与评测记录.md](05b-t2a-训练与评测记录.md)，本文只停在"准备"这一层。

### 1.1 为什么 torchaudio 必须是 2.9.0

torchaudio 与 torch 是 ABI 绑定的：2.9.0 对应 torch 2.9.x。更高的 torchaudio 版本会要求 torch ≥ 2.11，等于顺手把整套 torch 升级掉——而 Mimi 编码、bf16 autocast、`_foreach_lerp_` 都依赖 2.9 的行为。所以不要单独`pip install -U torchaudio`；要动就两边一起动，并重跑 05b 第 2 节那一步 `--eval_only`。

### 1.2 哪一步才真正需要语音识别依赖

- `encode.py --parts aud` 只用 torch + Hugging Face 的 Mimi，不需要 funasr。
- `sparrow.py --tasks t2a` 训练阶段同样不需要语音识别。
- 只有**评测**要加载 Paraformer，才需要 `funasr`、`pypinyin`、`librosa`、`transformers`；而且这四个包都是 `asr.py` 里的函数内延迟导入（见第 8 节③）。

## 2. 录音数据（实测）

### 2.1 五个键

文件 `repro\work\data\voice.npz`，**86,306,618 字节（86.3 MB）**，`np.load` 读出的键与形状：

| 键 | 形状 | 类型 | 含义 |
| --- | --- | --- | --- |
| `wav` | (432, 49920) | float32 | 24 kHz、2.08 s 的归一化波形 |
| `animal` | (432,) | int64 | 0–5，对应 `parts.py` 的 `ANIMALS`（猫、狗、兔、鸟、鱼、熊） |
| `voice` | (432,) | `<U5` | 12 个音色名，按说话人划分 |
| `test` | (432,) | bool | 测试集标记 |
| `name` | (432,) | `<U18` | 原始文件名 |

`test == True` 共 **108** 条，训练 324 条。

读完先对三个数（在仓库根目录执行）：

```powershell
python -c "import numpy as np;d=np.load(r'repro\work\data\voice.npz');print('rows',len(d['test']),'/ test',int(d['test'].sum()),'/ voices',len(set(d['voice'].tolist())))"
```

期望 `rows 432 / test 108 / voices 12`。`test` 不是 108，就是划分坏了：等于 432 表示训练集和测试集是同一批，等于 0 表示根本没有测试集。`voices` 不是 12，说明音色名被改过或文件被重写，2.2 的 9/3 划分也跟着失效。这两种情况训练都不会报错，只会让 05b 里的分数失去意义。

### 2.2 12 个音色与 9 / 3 划分

`te01f te02f te03m tr01f tr03f tr04f tr05f tr07m tr08m tr12m tr14f tr16f`

其中 9 个进训练、3 个只进测试，**按说话人划分**。所以 t2a 的测试集回答的是"换一个没听过的音色，还念不念得对"，不是"记住这个音色"。

### 2.3 49920 的来历

24 kHz × 2.08 s = 49920 个采样点；49920 = 26 × 1920。`parts.py` 里 `SR = 24000`、`AUD_FRAMES = 26`、`CLIP = AUD_FRAMES * MIMI_HOP`，Mimi 每 1920 个采样点（80 ms）出一帧，26 帧正好铺满一条录音。编码、训练、解码三处用的是同一组常量，改一处就要三处一起改。

### 2.4 为什么必须在潜空间生成

生成分支的损失是流匹配，在数据空间里做回归。如果直接对 49920 个波形采样点回归，相位和延迟会把 MSE 主导掉——参考实现做过这组对照：同一条链路，直接波形那条路生成出来的声音判分基本为零，换成 Mimi 连续潜变量才念得出词。所以"先编码"不是工程优化，是**这个任务能不能成立的前提**。

`frozen.py` 的 `Voice` 用的是 Mimi 的连续潜变量：24 kHz 输入、每 1920 点一帧，跳过码本只走量化器的输入/输出投影，得到每帧 512 维。进主干前由 `sparrow.py` 的 `tokens()` 把 `[N, 26, 512]` 重排成 `[N, 104, 128]`（`--aud_split 4`，每帧拆 4 个 128 维向量），解码时 `denorm` 之后再由 `Voice.decode` 还原。

体积账：原始 86.3 MB；编码后 fp16 缓存 1404 × 26 × 512 × 2 字节 = 37.4 MB；每条录音 26 × 512 = 13312 个数，相对 49920 个采样点压缩约 3.75 倍。

## 3. 音频缓存（已实跑）

### 3.1 命令与实测输出

```powershell
python encode.py --parts aud --data ..\..\repro\work\data --judges ..\..\repro\work\judges --out ..\..\repro\work\cache
```

实测输出（`encode.json` 里 aud 那一段）：

```json
{"repo": "kyutai/mimi", "params_M": 79.3, "load_seconds": 88.5, "encode_seconds": 20.2, "peak_mem_GB": 1.93, "cache_MB": 37.4, "latent": [26, 512]}
```

首次运行会下载 Mimi 权重（`model.safetensors` 约 385 MB），这 88.5 s 的加载里包含了一次性下载与初始化；第二次起会快很多。

输出对不上时，先看这几项：

- `cache_MB` 应在 37 上下。两百多 MB 说明 `--parts` 里带上了 `img`，白重编一遍。
- `latent` 必须是 `[26, 512]`。变了说明加载的不是 `kyutai/mimi`，或者 `AUD_FRAMES` 被改过。
- `peak_mem_GB` 1.93 是只编音频的量级；明显更高，通常是同一轮还编了别的零件。
- `load_seconds` 一直停在 80 s 以上，说明每次都在重新下载权重，模型缓存没有落到默认目录。
- 缺 `judge_img.pt` / `judge_vid.pt` 会在开头就崩：`encode.py` 不论编哪些零件，都先加载两个判卷器，报错早于任何编码输出。

### 3.2 产物里到底有什么

`repro\work\cache\aud.npz` 只有一个键：

| 文件 | 键 | 形状 | 类型 |
| --- | --- | --- | --- |
| `aud.npz` | `voice.aud_lat` | (1404, 26, 512) | float16 |

同批重写的 `labels.npz` 键：

- `train.img_animal` / `train.img_color` / `train.vid_animal` / `train.vid_color` / `train.vid_action`
- `test.img_animal` / `test.img_color` / `test.vid_animal` / `test.vid_color` / `test.vid_action`
- `voice.animal`、`voice.test`、`voice.wav_index`

`sparrow.py` 的 `Cache` 读的是"份.字段"这个命名：`voice.aud_lat` 落到 `self.voice["aud_lat"]`，`voice.wav_index` 用来把 1404 行映射回 0..431 条原始录音。

### 3.3 1404 行怎么来的

`encode.py` 文件头的 `AUG = 4`：训练录音每条做 4 份（原样 + 3 份随机后移 0–100 ms，且后移量被 `tail_room()` 限制在尾部静音里，**不截字**），测试录音只 1 份。顶层函数 `train_wavs(voice)` 负责这件事，`aud()` 与 `hear()` 拿到的是同一批波形。

于是缓存行数 = 324 × 4 + 108 = 1296 + 108 = **1404**。折合 432 条录音平均每条 3.25 行（432 × 3.25 = 1404），`voice.wav_index` 里存的就是那一行对应哪条原始录音。

这个增广只改"什么时候开口"，不改"念的是哪个词"，所以标签照抄 4 份。它和 t2i 的图像增广不是一回事：图像增广在造数据侧，音频增广在缓存编码侧。

### 3.4 覆盖检查（实测）

在仓库根目录跑这一条，把 `aud.npz` 与 `labels.npz` 对齐：

```powershell
python -c "import numpy as np;l=np.load(r'repro\work\cache\labels.npz');w=l['voice.wav_index'];v=np.load(r'repro\work\data\voice.npz');print('rows',len(w),'/ distinct',len(set(w.tolist())),'/ min',int(w.min()),'/ max',int(w.max()),'/ test_rows',int(l['voice.test'].sum()),'/ src_rows',len(v['wav']))"
```

期望输出：

```text
rows 1404 / distinct 432 / min 0 / max 431 / test_rows 108 / src_rows 432
```

六个数逐个对照：

| 观测值 | 期望 | 对不上说明什么 |
| --- | --- | --- |
| `rows` | 1404 | 不是 1404，说明增广份数不是 4，或录音条数变了 |
| `distinct` | 432 | 比 `src_rows` 小，说明有录音没进缓存，`wav_index` 指错了行 |
| `min` / `max` | 0 / 431 | 越界说明索引写错 |
| `test_rows` | 108 | 不等于 108，`voice.test` 的标记被改过 |
| `src_rows` | 432 | 与 `distinct` 不等，就是覆盖不全 |

六个数全对上，说明**每条录音都至少被用上、没有孤儿行，也没有越界索引**。换数据后值得重跑一遍：这里错位不会让训练报错，只会让标签全错。

### 3.5 和参考实现的 `encode.py` 差在哪

用 grep 核过：参考版 `encode.py` **不存归一化统计量**，命中的 `stats` 只是 `torch.cuda.reset_peak_memory_stats()`；它只做两件事——`np.savez` 写 `{part}.npz`、写 `labels.npz`。

因此两份 `encode.py` 的**产物格式完全一致**，已经编好的 `aud.npz` 不需要重编，省掉一次 88.5 s 加载 + 20.2 s 编码。差异共约 15 行，来源是：

- `dev = "cuda" if torch.cuda.is_available() else "cpu"` 的 CPU 兜底；
- `PARTS` 常量提到文件头，默认 6 种，**不含** `vidimg`（`job` 里该分支仍保留，需要时显式 `--parts vidimg`）；
- `train_wavs()` 提为顶层函数，而不是嵌在 `main()` 里；
- `os.makedirs(a.out, exist_ok=True)` 自动建输出目录。

归一化统计量不在缓存里，是训练时由 `sparrow.py` 的 `Cache` 现算、再写进 `final.pt` 的 `stat`。这也是 `--eval_only` 必须用"训练时那份权重"的原因（见第 8 节⑦）。

## 5. 一步训练里发生了什么

按 `sparrow.py` 的 `train()` 执行顺序拆。

**① 这个任务每步取几条**：`lay, B = lays[task], batch(a, task)`。`batch()` 里 `--bs_task` 单独给的优先，否则 `t2v` / `v2t` 用 `--bs_vid`，其余用 `--bs`。t2a 走 `--bs`。

**② 取样本、填条件 token**：`data.get(task, B, rs(task, "pick"))` 返回 `(slots, segs)`。`fill_tok(lay, slots, B, drop)` 把 `A` 槽位填成动物词 id；`drop` 有 **10%** 概率为真（`torch.rand(B) < 0.1`），此时该槽位换成 `<null>`。这 10% 就是 `--cfg 3.0` 能在推理时做条件/无条件插值的原因。

**③ 采样时间、构造加噪样本**：`t = torch.sigmoid(torch.randn(B))`（logit-normal，中段 t 更多）；`segs[-1] = (1 - t)·ε + t·x1`；模型吃 `(布局, token, 各段向量, t)`，输出速度 `v`。

**④ 损失只有一项**：`loss = F.mse_loss(v.float(), x1 - eps)`。t2a 的三个文字 token（`<bos>`、动物词、`<aud>`）都不带 `*` 答案标记，`lay.answer` 为空，所以**没有交叉熵项**，文字只当条件。这一点与 t2i 完全相同。

**⑤ 加权、反向、更新**：`(loss * a.weights.get(task, 1.0)).backward()`。默认 `--weights "t2a=4"`，即 t2a 的 MSE 乘 4，t2i 不写就是 1。

- 多个任务在一步里**串行**执行，梯度累加在同一份 `.grad` 上；之后 `clip_grad_norm_(..., 1.0)` 再 `opt.step()`，每步只更新一次参数。
- 优化器 `AdamW(lr=6e-4, weight_decay=0.01, betas=(0.9,0.99))`；学习率 `6e-4 × min(1,(step+1)/300) × (0.1+0.9·½(1+cos(π·step/steps)))`，即 300 步 warmup + 余弦退到 10%。
- EMA：`d = min(a.ema, (1+step)/(10+step))`，再用 `_foreach_lerp_` 更新；`final.pt` 存的是 EMA 权重。
- 没有 `GradScaler`、没有梯度累积、没有 `--precision` / `--grad_accum` 这两个参数；bf16 是写死的 `torch.autocast("cuda", torch.bfloat16)`。

**⑥ 梯度走到哪些参数**：t2a 这条路上被更新的是 `inp["aud"]` / `where["aud"]` / `when["aud"]` / `flow_head["aud"]` 四个音频专用模块（`inp`、`flow_head` 是 `nn.ModuleDict`，`where`、`when` 是 `nn.ParameterDict`），加上共享主干与位置/时间嵌入。所以：

- 只 `--tasks t2a`：主干只被音频梯度推动，t2i 能力会明显退化；
- `--tasks t2i,t2a`：img 模块靠 t2i 那一路保住，主干同时受两路梯度——"带练"的全部机制就这一句，没有别的开关。

## 6. 判分链路

`evaluate()` 开头无条件加载两个判卷器：`load_judge(ImageJudge, f"{a.judges}/judge_img.pt", dev)` 与 `VideoJudge`。即使只评 t2a，这两个文件也必须在 `--judges` 指向的目录里。

t2a 分支（`if "t2a" in tasks`）：

1. `ai = torch.arange(6).repeat_interleave(40)`：6 个动物 × 40 条 = **240** 条题；
2. `draw("t2a", {"A": ...}, len(ai))`：`draw()` 默认 `size=128`，即每块生成 128 条；
3. `voice.decode(data.raw("aud", x[s:e]))`：按 `chunks(len(x), 64)` 分块解码；
4. `from asr import Paraformer`，`judge = Paraformer(dev)`；
5. `judge.hits(...)` 返回 `(same_sound, exact, heard)`。

写进 `report.json` 的键：

| 键 | 含义 |
| --- | --- |
| `n` | 题数，240 |
| `judge` | 判卷器名，`paraformer-zh` |
| `sound_acc` | **主指标**：转写拼音（不计声调）与目标词相同即算对 |
| `exact_acc` | 逐字全对 |
| `sound_by_word` | 6 个词各自的对率 |
| `misheard` | 前 20 条判错的转写文本 |

样例在 `<out>/samples/gen_t2a_{k}_{词}.wav`，每个词一条。

`asr.py` 里判分相关的细节：

- `class Paraformer` 用 `AutoModel(model="paraformer-zh", hub="hf", disable_update=True)`；
- `sound()` 用 `lazy_pinyin` 转拼音且不保留声调，所以同音字不算错；
- `prep()` 先重采样到 16 kHz，再用 `librosa.effects.trim` 去首尾静音，最后两头各补 0.2 秒（3200 点）；
- 另一个 `class Asr`（Whisper-large-v3-turbo）是**造数据时的筛子**，本地判分不用它。

| `--tasks` | 全部 7 种 | 写哪些任务就练哪些 | `t2i,t2a` | 只写 `t2a` 会让 t2i 明显退化 |
| `--eval_tasks` | `""` | 只影响评测；空串时回落到 `--tasks`，`--eval_only` 时回落到权重里记录的那几样 | `t2i,t2a` | 评测会按它加载解码器与判卷器 |
| `--bs` | 512 | 每任务每步样本数；大→显存与单步时间线性涨 | 128（本轮取值；峰值随批大小变，实测见 05b 第 3 节） | 与本机显存绑定；再往上要先看 `train_peak_mem_GB` |

| `--init` | 无 | 从这份 `final.pt` 继续训；不写就是从零 | 参考实现权重或上一段自己的权重 | `dim/depth/heads/aud_split/maxlen` 必须一致 |

| `--ema` | 0.999 | EMA 衰减；大→更平滑、收敛慢 | 0.999 | 0.99–0.9999 |
| `--aud_split` | 4 | 每个 Mimi 帧拆几个向量；改小→序列短、每格维度大 | 4，不要改 | 与起点权重绑定，改了就加载失败 |
| `--cfg` | 3.0 | 只影响评测采样：大→更贴条件、更僵硬 | 3.0 | 1.0–5.0 |
| `--maxlen` | 400 | 位置表长度 | 400 | 必须 ≥ 各任务序列长度，t2a 是 107 |
| `--dim` / `--depth` / `--heads` | 384 / 8 / 6 | 模型规模 | 不动 | 与起点权重绑定 |
| `--seed` / `--rng` | 0 / `legacy` | 训练种子与随机协议 | 不动 | `paired` 才按任务分独立随机流 |
| `--eval_seed` | 0 | 评测起点噪声种子（第 i 题按 `eval_seed*10000+i`） | 0 | 同一批权重比较时不要换 |
| `--stop_at` | 0 | 学习率照 `--steps` 排，但练到第 N 步就停 | 0 | 用原样重走某段时才有意义 |
| `--eval_only` / `--ckpt` | 关 / 无 | 不训练，只评测 `--ckpt` | 第 1 关使用 | `--eval_only` 必须给 `--ckpt` |

| `--per_combo` / `--hold` / `--match_total` | 0 / `""` / 关 | 挑训练图子集（对照实验） | t2a 不用 | 只影响训练子集 |

## 8. 常见错误与对策

### ① Python 3.12 不允许在推导式的可迭代表达式里用海象运算符

```python
[... for x in (y := f())]   # SyntaxError: assignment expression cannot be used in a comprehension iterable expression
```

检查 npz 时很容易顺手写成"边读边赋值"。把赋值挪到推导式外面：

```python
d = np.load(p)
rows = [d[k] for k in d.files]
```

### ② PowerShell 里中文可能显示成乱码

`Get-Content` 默认按系统编码读，源码里的中文注释会变问号。要看真中文加 `-Encoding UTF8`。这只影响阅读，不影响 Python 执行。

### ③ `import asr` 成功不等于能评测

`funasr`、`pypinyin`、`librosa`、`transformers` 全都在 `asr.py` 的函数内部延迟导入：模块级 import 只加载 `re`、`numpy`、`torch`。所以 `python -c "import asr"` 通过，只说明语法和顶层依赖没问题；真正的依赖缺失要等到 `Paraformer.__init__` 或 `sound()` 才暴露。判断办法只有一个——**真的跑一次判分**（05b 第 2 节）。

### ④ 评测在训练结束之后才执行：训练成功、数字全丢

`main()` 的顺序是：`train()` → `save(..., "final.pt")` → `evaluate()` → `write_json(report.json)`。如果评测阶段抛异常，`final.pt` 已经落盘，但 `report.json` 写不出来——表现就是"训练成功，指标全无"。对策不是改代码，而是**把评测链路提前验证**：先跑 05b 第 2 节那一步，再开长跑。

### ⑤ `--out` 必须是新目录，脚本会拒绝覆盖

`fresh_out(out)` 会检查目录里是否已有运行产物（`report.json`、`summary.json`、`init.json`、`records.json`、`samples`、权重文件），若有就 `SystemExit`；它还会向上检查，如果 `--out` 落在别的运行目录里面（如 `runs/x/step1000`），同样拒绝。所以每轮实验换一个新目录名，报错文案是"不覆盖,换一个 --out"。

### ⑥ `--init` 的检查分两层

1. 先比结构：`dim`、`depth`、`heads`、`aud_split`、`maxlen`，不一致直接退出，文案是 `--init {路径} 的结构和这次不一致(起点权重, 这次):{...}`；
2. 再 `load_state_dict(..., strict=False)`，只允许缺 `seelat` / `vidimg` 这类可选表示（新初始化），其余缺键或多键都报 `--init 的权重对不上:缺 ... ,多 ...`。

所以从参考权重接着训时，不要改 `--aud_split`，也不要改模型规模。

### ⑦ `--eval_only` 的四个硬约束

- 必须给 `--ckpt`，否则 `SystemExit("--eval_only 要用 --ckpt 指定评测哪份权重")`；
- `--tasks` 会被置空、`--steps` 置 0、`--init` 置空——**真正决定评测范围的是 `--eval_tasks`**；`--eval_tasks` 为空时回落到那份权重训练时记录的 `eval_tasks` 或 `tasks`；
- `Cache(..., strict=True)` 要求权重里带着 `stat` 字典，缺任何一种要用的模态统计量都会报错（参考权重是训练时写进去的，所以能用）；
- 缓存缺文件会在**建 `Cache` 阶段**直接失败：评 t2a 要 `aud.npz`，评 t2i 要 `img.npz`；理解类任务（`i2t` / `a2t` / `v2t`）还要 `see.npz` / `watch.npz` / `hear.npz`。本轮只编了 `aud`，所以 `--tasks` 与 `--eval_tasks` 都要限定在 `t2i,t2a`。

另外，`--eval_only` **不写** `final.pt`，报告与样例写进 `--out`。

## 9. 三关验证路线

原则：每一关都要有一个能当场判真假的观测值，上一关不过就不进下一关。三关怎么跑、每一关的实测值、逐词分布与异常检查，全部在 [05b-t2a-训练与评测记录.md](05b-t2a-训练与评测记录.md)，本节只留路线。

| 关 | 做什么 | 该看什么数 | 为什么排在这一位 |
| --- | --- | --- | --- |
| 第 1 关 | 用一份已训权重跑 `--eval_only`，`--eval_tasks t2i,t2a` | `report.json` 生成；`eval.t2a.sound_acc` 与 `eval.t2i` 都有值；`eval_only.ckpt_sha256` 有值；样例 wav 能播放 | t2a 评测要在线加载 Paraformer 并真做语音识别，这条链最容易在评测阶段才炸 |
| 第 2 关 | `--tasks t2i,t2a` 起步训练，先看头 100 步 | 两个任务都出 loss；`train_peak_mem_GB` 可读；单步时间稳定；批大小能推到哪 | 只回答"装得下吗、数据通不通"，与"学得动吗"分开 |
| 第 3 关 | 全量训练 + `--eval_every` 中途评测 | 每个评测点的 `sound_acc` 在动，且训练不中断 | 回答"学得动吗" |
| 第 3 关（续训） | 从上一段权重接 `--init` 再训一段 | `init_sha256` 与父权重一致；末评不低于上一段；无 nan、无 OOM、无中断 | 一次跑两件事：验证权重加载路径，同时看"再训一点还有没有收益" |

两条说明：

- 第 1 关"算不算通过、以哪份权重为准"还没定。05b 如实记为"以参考实现权重跑通评测链，本地权重另行验证"，不按"已通过"计。
- 评测没有开关（脚本没有 `--no_eval`）。想省时间只能在冒烟时把 `--eval_tasks` 缩到最小，不能靠传空串跳过。
