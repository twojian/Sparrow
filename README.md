<div align="center">  <h1>Sparrow</h1>  <p><strong>Small Model. Full Spectrum.</strong></p>  <hr />  <h3>麻雀虽小，五脏俱全。</h3>  <p>一个面向轻量化、统一多模态理解与生成的开源模型项目</p></div>

目标是一台统一的多模态小模型：文字、图像、音频、视频共用一个 token 空间、进同一个主干，既能生成（文字→图像 / 音频 / 视频），也能理解（图像 / 音频 / 视频→文字）。

本仓库基于一套公开的多模态基线实现，完成了训练、评测、性能消融与工程化整理；下文标注为「实测」的数字均来自本仓库内的运行记录。

三个设计锚点：

- **统一序列**：每个模态先由冻结的 tokenizer 变成向量，与文字 token 排进同一条序列，进同一个 Transformer 主干。

- **双出口**：文本头做下一词预测，生成头用流匹配预测速度场；理解与生成共用主干，不建两套模型。

- **模态可插拔**：新增一个模态 = 接一组 tokenizer / 编码器 + 一层小投影 + 一个出口，主干形状不变。

当前状态：t2i（文字→图像）已在合成数据上跑通完整链路；t2a（文字→音频）尚未开训，缺语音录音数据与判分脚本（Mimi 编码器与训练/评测路径已就位）；其余任务有代码路径、未训练未评测。规模控制在单张 4 GB 级显卡可训练的范围（当前配置 16.04M 参数）。

## 一、目标形态

要做的是一个"小但完整"的多模态模型，而不是若干单任务模型的拼装：

- **一个主干**：所有任务共享 Transformer；理解与生成不再分家。

- **一套接口**：生成侧接各模态的 tokenizer（图像 VAE、音频编解码器、视频 VAE），理解侧接各模态编码器（视觉、语音），两侧都通过投影层汇入同一序列空间。

- **一组出口**：文本头负责所有"说出内容"的任务，生成头负责所有"产出连续信号"的任务。

- **单卡可训练**：参数规模与序列长度按 4 GB 显存预算设计，宁可小、也要端到端可跑、可评测、可复现。

## 三、架构设计

这一节讲设计意图与取舍；除 t2i 外的任务尚未训练，结构沿用同一套接口。

### 共享主干

一个 Transformer，当前配置 `dim=384`、8 层、6 头、最大长度 400、约 16.04M 参数。文字 token 与各模态的向量排成一条序列进主干。注意力掩码分三种：文字只看前文（因果）；同一段模态内部全互看；不同模态段之间不互看。视频可选"每个时间槽只看自己这一段"的隔离模式，用于控制序列内的干扰。

共享主干的理由是：模态间的对齐发生在同一组参数里，而不是靠跨模型蒸馏；任务越多，主干见到的信号越杂，单任务过拟合的倾向被摊平。

### 模态接口

- **生成侧**：在冻结的 tokenizer 潜空间里工作——图像 VAE 给 8×8=64 个潜向量（每个 32 维）、音频编解码器给 26 帧 × 512 维（`aud_split=4` 进序列时摊成 104 个 128 维向量）、视频 VAE 给 5 个时间槽 × 64 个向量（每个 16 维，覆盖 16 帧）。

- **理解侧**：冻结编码器 + 两层小投影——视觉编码器给 16 个（视频每个时间槽 2×2 再拼成 64 个）、语音编码器给 26 帧 × 384 维。

- **冻结部分只在训练前编码一次并缓存**，训练时只跑主干、投影与出口。这是在 4 GB 级显存预算内训起来的前提：把最贵的编码器移出训练回路。

### 任务头

- 文本头：`dim → 词表`，预测下一个词，覆盖看图 / 听声 / 看视频说话。

- 生成头：每个生成模态一个 `dim → 潜变量维度` 的速度头。

- 每个任务对应一条固定序列模板（`<bos>` + 条件 + 模态段 + 答案段），任务差异体现在序列与掩码上，而不是单独的模型。

### 为什么用流匹配

- 生成目标是连续向量（潜变量），流匹配天然适配，不需要把连续信号离散成词表。

- 三个生成模态共用一种训练目标：`z_t=(1-t)·噪声+t·数据`，回归速度 `v=数据-噪声`，损失形式统一，权重只需按任务调。

- 推理是一段确定的积分（Euler 30 步 + 条件强度 `cfg`），步数与强度都是显式旋钮，便于在低显存下按质量/延迟折中。

- 与离散扩散相比，它不需要为每个模态设计噪声表与采样器，接口成本最低。

## 四、数据策略

### 当前：合成数据只是脚手架

仓库里现在跑的是程序合成的卡通世界：64×64 RGB，8 色 × 6 动物 = 48 种组合，视频再多 4 种动作。它的用途只有一个——**打通"数据 → 编码 → 训练 → 评测 → 推理"这条链**：

- 验证缓存格式、序列模板、掩码、评测协议、权重导出与推理入口是否闭合；

- 验证流匹配在极小规模下确实收敛；

- 因为标签是程序生成的，判卷式评测可以做到完全自动、可重复。

**它不作为主干训练素材。** 这里的任何准确率都只说明管道通了，不构成模型能力；换成真实数据后，这些数字都会重算。

### 规划：真实训练数据

要让模型真的可用，还需要补齐四类数据与配套条件：

- **图文对**：真实照片 + 人工或高质量描述，覆盖物体、场景、颜色、动作等常见语义；需要许可清晰、去重、描述与图一致。

- **语音**：多说话人、多口音的短句，带转写；用于 t2a 的生成与 a2t / a2i 的理解侧。

- **视频片段**：短片段 + 动作/内容标签，帧率与分辨率按 tokenizer 的输入要求裁剪。

- **统一评测集**：每个任务一套固定题面与判分口径，避免"换个测试集数字就变好看"。

还需要解决的三件事：tokenizer 对真实分布的覆盖（现在的潜空间是按合成图调过的）、显存与序列长度预算（真实分辨率会显著拉长序列）、数据清洗与合规。

## 六、限制与边界

- **当前代码只带合成数据生成器**：真实图文 / 语音 / 视频的接入是规划，尚未实现。

- **只有一个任务真正训过**：t2i；其余 6 个任务只有代码路径与序列模板。

- **容量小**：16M 参数，在合成数据上只够学会 48 种组合与固定模板，换词、换构图、换画风都不行。

- **封闭词表**：输入必须是词表内的颜色 / 动物 / 动作词，不是自由句子；不具备开放域文本理解与生成。

- **分辨率低**：64×64 输出，细节有限。

- **显存约束**：4 GB 级单卡预算下，本机实测批大小 128 已接近上限（代码默认 `--bs` 为 512，实际跑需按显存下调）。

- **精度**：bf16 在无张量核的硬件上无加速，混合精度只省显存，不提速。
